# 当前需求

## 用户请求

阅读根目录 `README.md`，结合 `AGENTS.md` 的规范内容，运用 `create-agent-teams` 技能为“清研霍格精工拓客智能体”创建 agent 团队。

补充需求：当只有一条通告、采购公告、成果新闻或项目通知时，agent 团队需要能根据该通告从公开来源补全潜在用户联系人和联系方式状态，并严格区分通告流程联系人与真实技术需求方。

补充需求：客户经理人工复核结果中需要具体展示已公开确认的联系方式，并明确列出每条联系方式的来源 URL、来源页面标题、证据片段和采集日期。

补充需求：把“主控编排 agent 汇总结果后写入网页复核台数据文件”的流程加入现有 agent 协作。网页复核台读取 `outputs/dashboard/data/latest-run.js`，主控编排团队必须在数据契约质检通过后统一落盘。

## 项目目标理解

本项目不是高校教授名单采集器，而是面向科研样件制造场景的机会识别与客户开发 agent。核心目标是帮助客户经理判断：

1. 今天最该联系谁。
2. 为什么现在联系。
3. 应该找谁、怎么开口。

MVP 阶段只辅助判断，不自动触达客户。

## 当前文档交付范围

- 在 `docs/agent-teams/` 下建立团队总览、ownership map 和跨团队交接协议。
- 为每个独立 ownership 团队创建可执行章程。
- 明确每个团队的职责边界、启动读取、当前需求解释、交付物、协作接口、工作规则、汇报方式和质量门槛。
- 记录当前上下文不足处，避免团队依赖未明说的私有信息。
- 补充本地网页复核台输出交接：主控合并、数据契约质检、落盘脚本同步、客户经理人工复核。
- 新增 [dashboard-output-workflow.md](dashboard-output-workflow.md)，作为网页复核台输出流程的 agent 协作说明。

## 优先级

| 优先级 | 事项 | 原因 |
| --- | --- | --- |
| P0 | 团队边界必须对应 AGENTS.md 的 7 层业务边界 | 防止采集、识别、评分、联系人和话术混成不可追踪大步骤 |
| P0 | 明确可追溯字段和交接物 | 所有 AI 结果必须可追溯、可解释、可人工复核 |
| P0 | 明确 MVP 不自动触达 | 防止“话术已生成”被误标为“客户已联系” |
| P1 | 增加数据契约与质量保障团队 | 承接字段兼容、敏感信息、日志、测试和 Prompt 版本等横切规则 |
| P1 | 每个团队必须有启动汇报、进展汇报、完成汇报格式 | 让项目 owner 不读全部代码也能追踪进度 |
| P1 | 补齐通告驱动联系人补全子流程 | 支持从单条通告进入联系人识别，但不猜测联系方式 |
| P1 | 明确联系方式结果展示与来源字段 | 让客户经理能直接复核具体联系方式及其公开来源 |
| P1 | 把网页复核台落盘加入主控编排 | 让 agent 流水线结束后能自动更新可视化复核结果 |

## 约束

- 不修改 README 的业务定位、评分规则或字段定义。
- 可以新增只做字段校验和文件同步的落盘脚本；不调整 Prompt，不改变评分规则。
- 不采集真实客户数据，不生成真实触达名单。
- 不自动发送邮件、微信、短信或电话。
- 不通过姓名拼音、学校域名、学院域名或常见邮箱格式猜测联系方式。
- 不把采购办、招标代理或办公室联系人默认当作真实技术需求方。
- 公开确认的具体联系方式必须绑定来源 URL、来源页面标题、证据片段和采集日期。
- 未公开或待人工确认的联系方式不得用推测值补齐。
- 团队章程必须使用中文 Markdown。
- 当前仓库未发现源码、数据库 schema、Prompt 模板或固定回归样例集，团队章程需标注这些资料缺失。

## 已接受假设

- 目前项目处于设计和文档搭建阶段，团队章程优先服务后续开发与多 agent 协作。
- README 中的工作流和 AGENTS.md 中的 7 层边界是当前最高优先级的团队划分依据。
- MVP 默认输出 Excel/CSV，字段需兼容 README 中的 Excel 输出字段。
- 通告驱动联系人补全先以流程和字段契约形式纳入项目，具体自动化检索实现、Prompt 和回归样例后续补齐。
- 后续如果出现代码目录、数据库 schema、Prompt 模板或测试样例，应由对应团队和数据契约与质量保障团队更新本目录文档。
- 网页复核台目前作为本地静态输出层存在，只读取文件、筛选、展示和保存本地复核状态，不自动采集或触达。

## 开放问题

- 目标数据存储方案尚未确定：文件、数据库、表结构和迁移策略需要后续设计。
- Prompt 模板目录 `/prompts` 尚不存在，需要在实现阶段确定版本管理方式。
- 固定回归测试样例集尚不存在，需要在实现评分、信号识别、联系人和话术 Prompt 前创建。
- 敏感联系方式的权限模型、脱敏规则和导出审计机制尚未实现。
- 每日任务调度、采集源访问策略和反爬处理策略尚未定义。
- 联系人补全 Prompt、公开检索策略和“通告流程联系人 vs 真实技术需求方”的回归测试样例尚未实现。
- 真实工作流的结构化中间产物还未由各业务 agent 自动生成；当前落盘脚本先定义主控编排团队的最终写入边界。
