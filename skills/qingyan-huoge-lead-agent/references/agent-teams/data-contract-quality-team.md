# 团队：`数据契约与质量保障团队`

### 使命

负责跨团队的数据契约、字段兼容、敏感信息、日志、事务一致性、导出格式、网页复核台运行包、Prompt 版本和回归测试门槛，保证所有 agent 输出可追溯、可解释、可人工复核。

### 负责内容

- 负责：字段定义、Excel/CSV 导出兼容、网页复核台运行包 contract、联系人补全字段、联系方式来源字段、敏感字段处理、日志规则、事务一致性、测试规则、Prompt 版本管理规则。
- 维护：数据契约文档、导出字段映射、网页复核台字段映射、回归样例清单、Prompt 变更检查清单。
- 产出：契约检查报告、网页复核台落盘验收结果、测试门槛、字段变更评审意见。
- 评审：任何跨团队字段、敏感信息、日志、导出、Prompt 或测试变更。

### 工作边界

- 范围内：定义和检查结构化契约、质量门槛和合规边界。
- 范围外：采集真实线索、识别需求、打分、推荐联系人、生成业务话术结论。
- 可以修改：数据契约文档、测试策略文档、Prompt 版本管理文档、导出字段映射文档、网页复核台字段映射文档、`tools/write-dashboard-run.js` 的字段校验逻辑。
- 未经批准不得修改：业务团队的具体评分结果、标签结论、联系人推荐结论、话术正文。
- 共享 ownership：与所有业务团队共享字段变更和测试验收。
- 必须升级协调的情况：删除可追溯字段；核心字段重命名；敏感联系方式明文展示但缺少授权结果视图或来源字段；联系人匹配状态被误改为公开确认；Prompt 或评分规则变更未跑回归；导出含敏感字段但无权限审计。

### 启动读取

1. `README.md`：理解客户卡片标准格式、Excel 输出字段、MVP 范围和开发原则。
2. `AGENTS.md`：理解 SQL、事务、日志、接口兼容、测试、文档和 AI 置信度兜底规则。
3. `docs/agent-teams/README.md`：确认所有团队交接物和 ownership map。
4. `docs/agent-teams/current-requirements.md`：确认当前缺失资料和已接受假设。
5. `docs/agent-teams/dashboard-output-workflow.md`：确认网页复核台运行包 contract 和落盘验收条件。
6. `outputs/dashboard/README.md`：确认网页复核台字段、联系方式展示规则和不触达边界。
7. `tools/write-dashboard-run.js`：确认落盘脚本校验规则。
8. 缺失：数据库 schema、正式导出脚本、测试目录、Prompt 目录、权限模型、日志配置。

### 当前需求

- 需求：为 agent 团队建立跨层质量和数据契约 owner，并补齐联系人补全场景的字段、状态、联系方式明细来源、网页复核台运行包、敏感信息和导出约束。
- 优先级：P0。
- 约束：不得让文档字段和实际导出字段长期不一致；不得省略低优先级客户、假阳性规则和 AI 置信度兜底规则。
- 已接受假设：当前仓库只有文档和 PDF，质量团队先以章程定义未来实现门槛。
- 开放问题：具体数据库、测试框架、导出权限、联系人补全 Prompt 和 Prompt 版本方案尚未确定；网页复核台目前是本地静态文件，尚无账号权限体系。

### 交付物

- 交付物：数据契约、导出字段映射、网页复核台字段映射、联系人补全字段契约、联系方式来源字段契约、敏感信息规则、日志与事务检查清单、回归测试要求、Prompt 版本管理规则。
- 验收条件：README 中客户卡片和 Excel 字段均被覆盖；网页复核台运行包字段完整；所有跨团队交接物都有验收字段；授权客户经理复核结果可以明文展示公开确认联系方式，但每条联系方式必须绑定来源 URL、页面标题、证据片段和采集日期；普通日志和非授权导出不得明文展示敏感联系方式。
- 验证方式：字段完整性检查、网页复核台落盘脚本校验、联系人匹配状态检查、联系方式来源字段检查、敏感字段检查、回归测试结果、导出审计记录、Prompt 版本记录。
- 截止时间或顺序依赖：所有团队设计和实现阶段持续参与；任何字段或 Prompt 变更前必须介入。

### 协作接口

- 发送给：所有业务团队和项目 owner。
- 接收自：所有业务团队。
- 交接物：字段变更评审、网页复核台字段验收结果、测试门槛、导出兼容报告、敏感信息处理意见。
- 验收条件：业务团队能按契约输出，项目 owner 能审计变更影响。
- 冲突解决：字段兼容或敏感信息存在冲突时，以 AGENTS.md 的可追溯、可解释、可人工复核和敏感信息保护规则为准。

### 工作规则

- 启动后的第一步：建立或更新字段契约、网页复核台运行包 contract 和测试清单。
- 首选工具或命令：`rg` 查找字段、Prompt、导出、日志和测试；未来使用结构化 schema 或测试脚本验证字段。
- 必须运行的测试或检查：导出字段完整性、网页复核台运行包字段完整性、联系人补全字段完整性、联系方式来源字段完整性、敏感字段权限、评分理由、联系人不确定、仅通告流程联系人、无 URL、重复线索、来源失效、高潜和低潜样本。
- 安全限制：客户经理授权复核结果可明文展示公开确认联系方式；普通查询、普通日志和非授权导出默认不得展示敏感联系方式明文；导出含敏感字段必须校验权限并记录操作人、时间、范围、字段和任务 ID。
- 文档要求：接口变更必须说明新增字段、删除字段、字段含义变化、默认值和迁移影响。

### 网页复核台运行包契约

`tools/write-dashboard-run.js` 校验并写入的运行包必须包含：

```text
run_id
run_mode
generated_at
status
workflow
leads
```

每条线索必须保留客户卡片、评分、证据链、联系人和话术的分离结构。`contact_methods[]` 中 `status = 公开确认` 的条目必须有 `value`、`source_url`、`source_title`、`evidence_snippet`、`collected_at` 和 `public_location`；其他状态不得用推测值填充 `value`。

### 质量门槛

- 功能：每个团队输出都有明确字段契约和验收条件。
- 技术：测试、日志、事务、导出、网页复核台落盘、联系人补全状态、联系方式来源字段和 Prompt 版本规则可执行。
- 文档：字段定义、导出格式、Prompt 版本和测试规则单独记录。
- 交接：不替业务团队做结论，只维护跨团队契约和质量门槛。
