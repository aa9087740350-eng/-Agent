# Agent 团队总览

本文档定义“清研霍格精工拓客智能体”的 agent 团队 ownership、交接协议和启动规则。团队划分严格对应 `README.md` 和 `AGENTS.md` 的分层边界：目标画像、公开采集、需求识别、动态评分、联系人识别、客户卡片与话术、销售反馈与模型优化，以及跨层数据契约与质量保障。

MVP 阶段所有团队只辅助客户经理判断，不自动发送邮件、微信、短信或电话。

## 跨团队交接协议

每次交接必须包含来源团队、接收团队、交接物、验收条件和阻塞项。缺失关键字段时不得静默补齐，应标记为 `未识别`、`未公开` 或 `待人工确认`。

| 来源团队 | 接收团队 | 交接物 | 验收条件 |
| --- | --- | --- | --- |
| 目标画像配置团队 | 公开线索采集团队 | 目标区域、目标高校/机构、客户类型、优先学科、排除规则 | 配置可追溯到 README 或项目 owner 明确要求，未硬编码为不可配置逻辑 |
| 公开线索采集团队 | 需求信号识别团队 | 原始线索包：线索 ID、采集日期、学校/机构、学院/实验室、负责人或团队、标题、证据片段、来源 URL | 每条线索至少有来源 URL、采集日期、标题、证据片段 |
| 需求信号识别团队 | 动态评分排序团队 | 标签包：研究方向、显性需求信号、痛点信号、近期紧迫信号、切入点、假阳性风险 | 标签不得覆盖原始证据；无显性需求和痛点时必须明确为空 |
| 动态评分排序团队 | 联系人识别团队 | 评分包：评分、优先级、评分理由、规则版本、兜底规则触发情况 | 评分等级稳定为 `A+ / A / B / C / D`；`A+` 和 `A` 至少有可追溯近期需求或痛点信号 |
| 联系人识别团队 | 客户卡片与话术团队 | 联系人包：推荐联系人、联系人身份、联系方式状态、推荐理由、公开来源 | 联系方式未公开时必须标记状态，不得猜测 |
| 客户卡片与话术团队 | 数据契约与质量保障团队、主控编排团队 | 触达建议包：客户卡片、联系方式明细、话术、建议动作、下次跟进时间 | 只标记为“话术已生成”或“待人工确认”，不得标记为“已联系”；字段可映射到网页复核台 run contract |
| 数据契约与质量保障团队 | 主控编排团队 | 网页复核台字段验收结果、缺失字段、敏感联系方式检查结果 | 公开确认联系方式均有来源 URL、页面标题、证据片段和采集日期；未公开联系方式无推测值 |
| 主控编排团队 | 本地网页复核台 | `outputs/dashboard/data/latest-run.js` 和 `outputs/dashboard/data/latest-run.json` | 页面可展示线索列表、评分理由、证据链、联系方式来源、话术和人工复核表单 |
| 本地网页复核台 | 销售反馈优化团队 | 客户经理导出的复核记录 JSON 或人工录入反馈 | 复核结论与真实触达反馈分开，不得把“话术已生成”误标为“已联系” |
| 销售反馈优化团队 | 动态评分排序团队、需求信号识别团队 | 反馈摘要、假阳性复盘、标签权重 review 建议 | 权重调整建议必须基于反馈数据，不得凭感觉调参 |
| 所有团队 | 数据契约与质量保障团队 | 字段变更、Prompt 变更、导出变更、敏感字段处理变更 | 说明新增字段、删除字段、默认值、迁移影响和测试覆盖 |

## 通告驱动联系人补全协议

当用户只提供一条通告、采购公告、成果新闻或项目通知时，主控编排团队必须启动 [contact-enrichment-workflow.md](contact-enrichment-workflow.md) 中的子流程。该流程的目标不是“猜出联系方式”，而是从公开来源中区分通告流程联系人和真实技术需求方，并输出可人工复核的联系人补全包。

最小推进顺序：

```text
通告事实提取
  -> 需求信号确认
  -> 公开联系人补全
  -> 敏感字段与来源检查
  -> 客户卡片使用联系人状态
```

关键规则：

- 通告中的采购办、招标代理或办公室联系人只能先标记为流程联系人。
- 真实技术需求方必须通过项目名称、学院/实验室、研究方向、设备用途或公开页面交叉验证。
- 无法公开确认联系方式时，必须标记 `未公开` 或 `待人工确认`。
- 联系人匹配状态必须区分 `公开确认`、`方向匹配待人工确认`、`仅通告流程联系人` 和 `未识别`。
- 普通页面、普通日志和普通导出默认不得展示明文邮箱、手机号或微信号。

## 自动推进协议

自动推进由主控编排团队负责。业务团队之间不直接假设彼此会监听任务；主控编排团队必须显式发送下游输入、等待完成、检查交接验收条件，再推进下一步。

默认推进顺序：

```text
目标画像配置
  -> 公开线索采集
  -> 需求信号识别
  -> 动态评分排序
  -> 联系人识别
  -> 客户卡片与话术
  -> 数据契约质检
  -> 主控合并并写入网页复核台
  -> 客户经理人工复核
  -> 销售反馈优化
```

数据契约与质量保障团队不在业务流水线中产出客户结论，但必须在字段、Prompt、导出、敏感信息、测试或规则版本变更时介入。

主控编排团队必须遵守：

- 不替任何业务团队做专业判断。
- 不修改上游证据、标签、评分、联系人或话术。
- 不跳过验收条件推进下游。
- 不自动发送邮件、微信、短信或电话。
- 当下游输入缺失时，退回上游补齐或标记 `未识别`、`未公开`、`待人工确认`。
- 流水线完成后只输出“客户经理待复核包”，不得标记为“已联系”。
- 只收到单条通告时，必须按通告驱动联系人补全协议推进，不得跳过公开验证路径。
- 写入网页复核台前，必须先生成 `outputs/workflow/latest-run.json`，再运行 `tools/write-dashboard-run.js` 同步到 `outputs/dashboard/data/latest-run.json` 和 `outputs/dashboard/data/latest-run.js`。
- 不允许任一业务团队直接覆盖 `outputs/dashboard/data/latest-run.js`；该文件只能由主控编排团队在数据契约质检通过后统一写入。

## 共享数据底线

每条线索至少包含：

```text
线索ID
采集日期
学校/机构
学院/实验室
负责人或团队
需求信号
证据片段
来源URL
评分
评分理由
```

联系人补全场景还必须包含：

```text
通告标题
通告联系人
通告联系人身份
通告联系人来源URL
联系人匹配状态
联系方式状态
联系方式展示状态
联系方式来源URL
联系方式来源页面标题
联系方式证据片段
联系方式采集日期
公开位置说明
推荐置信度
待人工确认事项
```

客户经理人工复核结果中，`联系方式状态 = 公开确认` 的联系方式必须具体展示，并逐条列出来源 URL、来源页面标题、证据片段和采集日期。`未公开` 或 `待人工确认` 不得用推测值补齐。

网页复核台运行包必须包含：

```text
run_id
run_mode
generated_at
status
workflow
leads
```

每条 `leads[]` 至少包含：

```text
lead_id
collected_at
institution
lab
owner
title
research_direction
potential_need
explicit_signals
pain_signals
urgency_signals
budget_or_project
recommended_service
entry_point
priority
score
score_reason
source_url
follow_status
contact
contact_methods
evidence
outreach
```

主控编排团队负责把业务团队输出映射为以上字段；数据契约与质量保障团队负责检查字段完整性和敏感联系方式来源完整性。

MVP Excel/CSV 输出必须兼容 `README.md` 中的字段，不得随意重命名 `评分`、`评分理由`、`信息来源URL`、`跟进状态` 等核心字段。

## 升级触发

出现以下情况必须暂停当前团队单独决策并升级给项目 owner 或相关团队：

- 需要调整评分规则、核心识别 Prompt、联系人推荐 Prompt 或话术 Prompt。
- 新增字段影响 README 定义的客户卡片或 Excel 输出。
- 采集源无法访问、来源失效或疑似反爬，可能影响批量结果。
- 联系方式、手机号、微信号、邮箱等敏感字段需要入库或导出。
- 具体联系方式缺少来源 URL、证据片段或采集日期，却被要求进入客户经理复核结果。
- 网页复核台数据落盘缺少必备字段、公开确认联系方式来源不完整，或落盘脚本校验失败。
- 联系人补全结果需要把 `方向匹配待人工确认` 升级为 `公开确认`，但证据链不足。
- 某类标签连续 `10` 次出现“无实物需求”“只是理论研究无实物”或等价负反馈。
- 高评分线索缺少可追溯近期需求信号或痛点信号。
- 团队想跨层修改其他团队的结论或原始证据。

## 汇报协议

每个团队必须按章程输出三类汇报：启动汇报、进展汇报、完成汇报。汇报必须包含可验证证据，例如文件路径、字段名、命令结果、数据源 URL、任务 ID 或产物链接。

项目 owner 可只阅读本文件、[current-requirements.md](current-requirements.md) 和各团队完成汇报来判断进度。
