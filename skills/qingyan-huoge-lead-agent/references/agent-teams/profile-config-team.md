# 团队：`目标画像配置团队`

### 使命

负责“目标区域与客户画像层”的配置和边界维护，确保后续采集只围绕可解释的区域、机构类型、优先学科和排除规则展开。

### 负责内容

- 负责：目标区域、区域权重、目标高校/机构、客户类型、优先学科、排除规则。
- 维护：MVP 区域配置、目标客户画像说明、低优先级或暂缓开发对象定义。
- 产出：面向采集团队的目标范围配置和排除规则清单。
- 评审：任何硬编码学校、地区、客户类型或学科方向的变更。

### 工作边界

- 范围内：编辑目标画像、区域权重、机构类型、学科方向和排除规则相关文档或配置。
- 范围外：采集网页、识别需求信号、计算评分、推荐联系人、生成话术。
- 可以修改：README 或配置文档中明确属于“目标区域与客户画像层”的章节；未来配置文件中对应目标画像的字段。
- 未经批准不得修改：评分公式、需求信号关键词、话术规则、销售反馈状态。
- 共享 ownership：与数据契约与质量保障团队共同维护画像配置字段命名和默认值兼容。
- 必须升级协调的情况：新增区域或客户类型会影响评分权重、采集范围、Excel 输出字段或 MVP 边界。

### 启动读取

1. `README.md`：理解项目定位、目标客户、MVP 范围和默认区域配置。
2. `AGENTS.md`：确认本团队只能负责目标区域与客户画像层。
3. `docs/agent-teams/current-requirements.md`：确认当前需求和已接受假设。
4. `docs/agent-teams/README.md`：确认与采集团队、评分团队的数据交接边界。
5. 缺失：目标画像配置文件；应承载区域权重、目标机构、优先学科、排除规则和版本。

### 当前需求

- 需求：为后续 agent 团队定义目标画像配置 ownership。
- 优先级：P0。
- 约束：不得把 MVP 默认高校和区域写成不可配置的长期硬编码逻辑。
- 已接受假设：当前项目尚无配置文件，本团队先以文档章程定义边界。
- 开放问题：未来配置格式使用 JSON、YAML、数据库表还是后台配置页尚未确定。

### 交付物

- 交付物：目标范围配置说明、排除规则说明、画像字段定义建议。
- 验收条件：每个目标范围都能追溯到 README、AGENTS 或项目 owner 明确要求。
- 验证方式：人工检查配置是否只包含区域、机构、客户类型、学科和排除规则。
- 截止时间或顺序依赖：必须早于公开线索采集任务启动。

### 协作接口

- 发送给：公开线索采集团队、动态评分排序团队、数据契约与质量保障团队。
- 接收自：项目 owner、销售反馈优化团队。
- 交接物：目标区域、区域权重、目标高校/机构、客户类型、优先学科、排除规则、配置版本。
- 验收条件：采集团队能据此确定采集范围；评分团队能据此计算基础匹配分。
- 冲突解决：画像规则与销售反馈冲突时，由销售反馈优化团队提供样本证据，项目 owner 决定是否调整。

### 工作规则

- 启动后的第一步：确认变更是否只属于目标区域与客户画像层。
- 首选工具或命令：`rg` 查找画像、区域、客户类型相关字段；人工对照 README 和 AGENTS。
- 必须运行的测试或检查：如果未来存在配置测试，必须验证默认区域、排除规则和向后兼容字段。
- 安全限制：不得引入敏感联系人字段；不得输出教授名单或邮箱列表。
- 文档要求：画像规则变更必须同步记录变更原因、默认值和影响范围。
