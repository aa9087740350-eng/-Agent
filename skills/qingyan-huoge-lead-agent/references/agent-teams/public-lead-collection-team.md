# 团队：`公开线索采集团队`

### 使命

负责“公开线索采集层”，从公开来源采集可追溯线索和证据片段，为后续需求识别提供原始事实。

### 负责内容

- 负责：高校官网、学院新闻、课题组主页、导师主页、论文摘要、专利摘要、采购公告、招聘、成果转化新闻、科技园企业名单、公众号文章等公开来源采集。
- 维护：数据源清单、采集范围、采集任务状态、去重规则输入特征。
- 产出：原始线索包、来源 URL、采集日期、标题、证据片段。
- 评审：采集源变更、采集字段变更、反爬或访问失败处理。

### 工作边界

- 范围内：采集公开事实，记录来源、时间、标题和证据片段。
- 范围外：需求信号判断、评分排序、联系人回应概率判断、话术生成。
- 可以修改：采集源清单、采集任务配置、原始线索字段说明。
- 未经批准不得修改：评分等级、评分理由、需求信号标签、话术内容。
- 共享 ownership：与数据契约与质量保障团队共同维护原始线索字段和日志规则。
- 必须升级协调的情况：来源失效、网页结构变化、批量失败、需要存储敏感联系方式、去重策略可能删除有效证据。

### 启动读取

1. `README.md`：理解公开信息源、MVP 覆盖高校和客户开发目标。
2. `AGENTS.md`：确认采集层必须保留 URL、采集日期、标题和证据片段，不得直接评级。
3. `docs/agent-teams/current-requirements.md`：确认当前不采集真实客户数据，只创建团队章程。
4. `docs/agent-teams/profile-config-team.md`：确认上游目标范围交接物。
5. `docs/agent-teams/data-contract-quality-team.md`：确认字段、日志、敏感信息和去重底线。
6. 缺失：采集源配置、采集脚本、任务状态 schema；应承载数据源、关键词、时间范围、任务状态和失败原因。

### 当前需求

- 需求：定义采集团队的职责边界和交接格式。
- 优先级：P0。
- 约束：不得输出单纯教授名单、邮箱列表或机构名单；不得猜测联系方式。
- 已接受假设：当前只建立文档，不执行真实网页采集。
- 开放问题：采集技术栈、任务调度、反爬策略和数据存储方案尚未确定。

### 交付物

- 交付物：原始线索包。
- 验收条件：每条线索至少包含线索 ID、采集日期、学校/机构、学院/实验室、负责人或团队、标题、证据片段、来源 URL。
- 验证方式：抽样检查来源 URL 可访问性、证据片段是否来自来源、日志是否包含任务 ID 和失败原因。
- 截止时间或顺序依赖：接收目标画像配置后启动，完成后交给需求信号识别团队。

### 协作接口

- 发送给：需求信号识别团队、数据契约与质量保障团队。
- 接收自：目标画像配置团队。
- 交接物：原始线索包、采集任务状态、跳过原因、失败来源列表。
- 验收条件：下游能基于证据片段判断需求信号，不需要回头猜来源。
- 冲突解决：下游认为证据不足时，采集团队补充来源或标记为证据不足，不得编造。

### 工作规则

- 启动后的第一步：确认采集范围来自目标画像配置团队。
- 首选工具或命令：`rg` 查找现有采集代码或配置；未来采集脚本需记录结构化日志。
- 必须运行的测试或检查：采集任务幂等性、去重范围验证、来源 URL 和证据字段完整性。
- 安全限制：不得把完整邮箱、手机号、微信号写入普通日志；未公开联系方式标记为 `未公开`。
- 文档要求：新增数据源必须说明来源类型、字段、访问限制、失败处理和去重特征。

### 质量门槛

- 功能：原始线索可被需求识别团队直接消费。
- 技术：批量任务幂等，失败不丢弃已成功采集证据。

- 交接：证据链完整，不含最终评分结论。
