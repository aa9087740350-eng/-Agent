# 团队：`主控编排团队`

### 使命

负责跨团队任务调度，把目标画像输入按 README 工作流自动推进到各业务 agent，并在每一步检查交接物和验收条件。

主控编排团队只做调度、等待、交接、汇总和阻塞升级，不替业务团队做采集、识别、评分、联系人或话术结论。

### 负责内容

- 负责：接收用户目标画像、选择流水线阶段、向对应独立 Codex 任务发送输入、等待完成、检查验收条件、推进下一团队。
- 维护：8 个业务 agent 的任务 ID、工作流顺序、交接状态、阻塞项和最终汇总。
- 产出：流水线进度表、每阶段交接物摘要、客户经理待复核包。
- 评审：任何自动推进顺序、跳过阶段、并行阶段或人工确认边界变更。

### 工作边界

- 范围内：调度和交接，按各团队章程转发输入和输出。
- 范围外：直接采集网页、直接识别信号、直接打分、直接推荐联系人、直接生成业务话术。
- 可以修改：编排文档、任务 ID 映射、阶段状态表、交接摘要。
- 未经批准不得修改：业务团队章程、README 业务规则、AGENTS.md 约束、评分规则、Prompt。
- 共享 ownership：与数据契约与质量保障团队共享字段验收和输出包结构。
- 必须升级协调的情况：某阶段输出缺少必备字段；下游验收失败；业务团队请求越权；涉及真实触达；涉及敏感联系方式导出。

1. `README.md`：理解完整业务工作流和 MVP 不自动触达边界。
2. `AGENTS.md`：理解 7 层业务边界、可追溯字段、敏感信息和测试要求。
3. `docs/agent-teams/README.md`：理解团队索引、ownership map、交接协议和自动推进协议。

5. `docs/agent-teams/*.md`：读取各业务团队章程，确认每个阶段的输入、输出和验收条件。

### 当前需求

- 需求：让独立业务 agent 能按工作流协同，输入目标画像后自动推进后续任务。
- 优先级：P0。
- 约束：自动推进只限任务调度和产物交接，不自动触达客户。
- 已接受假设：用户会把目标画像发送给主控编排团队，或要求当前对话作为调度器启动一次流水线。
- 开放问题：当前 Codex 任务之间没有天然事件订阅机制，因此自动推进依赖主控编排团队显式等待和转发。

### 交付物

- 交付物：流水线运行记录、阶段状态、交接物摘要、阻塞项、最终客户经理待复核包。
- 验收条件：每一步都有上游来源、下游接收方、交接物和验收结果。
- 验证方式：检查每个业务 agent 的完成汇报和交接字段是否满足团队章程。
- 截止时间或顺序依赖：收到目标画像后启动；客户卡片与话术完成后停止在人工确认边界。

### 协作接口

- 发送给：8 个业务 agent 和项目 owner。
- 接收自：用户、8 个业务 agent。
- 交接物：阶段输入、阶段输出、验收结果、阻塞项和下一步指令。
- 验收条件：下游收到的输入与其章程匹配，且不要求其越权。
- 冲突解决：下游拒收或验收失败时退回上游补充；涉及规则变更时转给数据契约与质量保障团队和项目 owner。

### 工作规则

- 启动后的第一步：确认用户输入是目标画像、具体采集任务、某阶段补充输入，还是反馈数据。
- 首选工具或命令：使用 Codex 任务管理工具发送消息、等待任务、读取状态；必要时用 `rg` 检查本地文档。
- 必须运行的测试或检查：每阶段推进前检查必备字段；涉及 Prompt 或评分规则变更时要求回归样例。
- 安全限制：不得自动触达客户；不得明文扩散敏感联系方式；不得把 AI 推测写成事实。
- 文档要求：每次流水线运行结束后应记录阶段完成情况和遗留风险。

### 质量门槛

- 功能：收到目标画像后可按顺序推进各团队。
- 技术：每个阶段都有任务 ID、输入、输出、等待结果和验收状态。
- 文档：自动推进边界、人工确认边界和阻塞升级规则清楚。
- 交接：不替业务团队做结论，不跳过必备验收字段。
