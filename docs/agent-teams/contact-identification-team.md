# 团队：`联系人识别团队`

### 使命

负责“联系人识别层”，按回应概率从公开信息中推荐联系人，并说明推荐依据和联系方式公开状态。

### 负责内容

- 负责：联系人候选识别、身份分类、回应概率依据、联系方式状态标记。
- 维护：联系人优先级规则、联系人推荐 Prompt、联系人证据字段。
- 产出：联系人包。
- 评审：联系人身份规则、联系方式处理、敏感字段展示和导出申请。

### 工作边界

- 范围内：基于公开来源推荐博士/硕士作者、实验室工程师、博后/项目助理、PI、科研秘书等联系人。
- 范围外：猜测邮箱或微信、自动触达、修改评分、生成完整话术正文。
- 可以修改：联系人推荐规则文档、联系人 Prompt、联系人测试样例。
- 未经批准不得修改：原始证据、评分等级、销售跟进状态。
- 共享 ownership：与数据契约与质量保障团队共同维护敏感联系方式脱敏、权限和导出审计规则。
- 必须升级协调的情况：需要存储或导出明文联系方式；公开来源无法确认联系人；联系人身份与证据冲突。

### 启动读取

1. `README.md`：理解联系人优先级和推荐理由要求。
2. `AGENTS.md`：确认不得猜测邮箱、电话或微信号，必须说明回应概率依据。
3. `docs/agent-teams/scoring-prioritization-team.md`：确认接收的评分包字段。
4. `docs/agent-teams/data-contract-quality-team.md`：确认敏感信息和导出规则。
5. 缺失：联系人推荐 Prompt、联系人测试样例、敏感字段权限模型。

### 当前需求

- 需求：定义联系人识别团队的权限，避免从评分或线索中虚构联系人。
- 优先级：P0。
- 约束：无法确认时必须标记为 `未识别`、`未公开` 或 `待人工确认`。
- 已接受假设：当前只创建团队章程，不处理真实联系人。
- 开放问题：明文联系方式的存储、脱敏展示和导出权限尚未实现。

### 交付物

- 交付物：联系人包。
- 验收条件：包含推荐联系人、联系人身份、联系方式状态、推荐理由、公开来源；不确定信息有明确标记。
- 验证方式：测试覆盖有公开联系人、无公开联系人、联系人不确定场景。
- 截止时间或顺序依赖：接收评分包后启动，完成后交给客户卡片与话术团队。

### 协作接口

- 发送给：客户卡片与话术团队、数据契约与质量保障团队。
- 接收自：动态评分排序团队、公开线索采集团队。
- 交接物：联系人包和证据引用。
- 验收条件：话术团队能知道应该称呼谁、为什么找他、联系方式是否可用。
- 冲突解决：证据不足时退回采集团队补充或标记待人工确认，不得猜测。

### 工作规则

- 启动后的第一步：检查候选联系人是否来自公开来源。
- 首选工具或命令：`rg` 查找联系人规则、Prompt 和测试；未来普通查询默认不展示敏感联系方式明文。
- 必须运行的测试或检查：联系人 Prompt 变更后跑固定回归样例，覆盖公开、无公开、不确定三类场景。
- 安全限制：不得通过姓名拼音、学校域名、学院域名或常见邮箱格式猜测邮箱。
- 文档要求：推荐理由必须说明回应概率依据，例如直接参与实验、负责装置、负责项目推进。

### 质量门槛

- 功能：联系人推荐能回答“应该找谁”。

- 文档：推荐理由和证据来源完整。
- 交接：不包含猜测联系方式，不执行触达。
