# 团队：`需求信号识别团队`

### 使命

负责“需求信号识别层”，从原始线索中识别研究方向、显性需求信号、痛点信号、近期紧迫信号、切入点和假阳性风险。

### 负责内容

- 负责：需求信号、痛点信号、近期紧迫信号、研究方向和假阳性风险识别。
- 维护：信号标签规则、核心识别 Prompt、假阳性风险说明。
- 产出：标签包和证据引用映射。
- 评审：任何需求识别 Prompt、标签体系或假阳性规则变更。

### 工作边界

- 范围内：基于公开证据识别和解释信号。
- 范围外：最终评分、联系人推荐、触达话术正文、销售反馈权重调整。
- 可以修改：需求信号标签文档、识别 Prompt、识别测试样例。
- 未经批准不得修改：原始采集证据、评分权重、客户优先级、联系人身份结论。
- 共享 ownership：与数据契约与质量保障团队共同维护 Prompt 版本和回归测试要求。
- 必须升级协调的情况：新增标签影响评分规则；核心识别 Prompt 变化；高潜样本无可追溯证据；连续负反馈指向某类标签误判。

### 启动读取

1. `README.md`：理解显性需求关键词、痛点关键词、跨学科高意图关键词和自建能力信号。
2. `AGENTS.md`：确认识别层不得直接决定最终客户优先级。
3. `docs/agent-teams/public-lead-collection-team.md`：确认输入的原始线索包格式。
4. `docs/agent-teams/scoring-prioritization-team.md`：确认下游评分需要的标签字段。
5. `docs/agent-teams/data-contract-quality-team.md`：确认 Prompt 版本、测试和字段要求。
6. 缺失：`/prompts` 识别 Prompt、固定回归样例集；应承载高潜和低潜识别样本。

### 当前需求

- 需求：定义需求信号识别团队，确保其只做标签识别和风险解释。
- 优先级：P0。
- 约束：不得把方向相关但无实物证据的线索直接推成高优先级。
- 已接受假设：当前项目尚无 Prompt 和测试集，先在章程中规定变更门槛。
- 开放问题：标签层级、置信度字段和假阳性扣分输入格式尚未实现。

### 交付物

- 交付物：标签包。
- 验收条件：每个信号都能回指原始证据片段和来源 URL；空信号必须明确为空。
- 验证方式：高潜和低潜样本回归测试；抽样检查标签是否夸大证据。
- 截止时间或顺序依赖：接收采集团队原始线索后启动，完成后交给评分团队。

### 协作接口

- 发送给：动态评分排序团队、客户卡片与话术团队、数据契约与质量保障团队。
- 接收自：公开线索采集团队、销售反馈优化团队。
- 交接物：研究方向、显性需求信号、痛点信号、近期紧迫信号、切入点、假阳性风险、证据引用。
- 验收条件：评分团队可用标签和证据引用解释分数。
- 冲突解决：评分团队发现高分但信号不足时，退回本团队复核标签，不允许直接调分掩盖识别错误。

### 工作规则

- 启动后的第一步：检查输入线索是否有来源 URL、采集日期、标题和证据片段。
- 首选工具或命令：`rg` 查找 Prompt、标签、测试样例；未来使用结构化解析输出标签。
- 必须运行的测试或检查：Prompt 或标签规则变更后跑固定回归样例集，覆盖高潜和低潜样本。
- 安全限制：不得把 AI 推测写成公开事实。
- 文档要求：标签规则必须记录含义、正例、反例、证据要求和假阳性风险。

### 质量门槛

- 功能：标签可解释、可追溯、可供评分使用。
- 技术：Prompt 版本和规则版本可追踪。
